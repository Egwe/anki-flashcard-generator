Anki Flashcard Generator

Erstelle Karteikarten aus deinen Dokumenten. Das Programm liest eine lokale Datei, erzeugt Karten mit einem KI-Modell und speichert ein Anki-Paket.

In fünf Schritten starten Alle Befehle ansehen

Für die Befehlszeile · Offline lesbar · Keine externen Ressourcen nötig

Direkt zu:

Der Zweck

Was macht das Programm?

Du gibst ein Dokument und ein KI-Modell an. Das Programm erstellt daraus Fragen und Antworten. Du erhältst eine Datei mit der Endung .apkg. Diese Datei öffnest du in Anki.

1

Dokument wählen

Nutze eine Datei auf deinem Computer. Möglich sind PDF, DOCX, HTML, Markdown und Text.

2

Karten erstellen

Wähle ein KI-Modell. Bestimme die Anzahl und die Sprache der Karten. Prüfe die Karten bei Bedarf als JSON-Datei.

3

In Anki lernen

Erstelle ein neues Deck oder ergänze ein vorhandenes Paket. Importiere die .apkg-Datei in Anki.

Wichtig: Prüfe die Karten.

Ein KI-Modell kann Fehler machen. Kontrolliere den Inhalt vor dem Lernen. Nutze dafür die Option --json.

Was das Programm nicht macht
  • Das Programm ändert nicht direkt deine persönliche Anki-Sammlung. Es bearbeitet nur die angegebene .apkg-Datei.
  • Das Programm lädt keine Internetadressen als Quelle. Nutze eine lokale Datei.
  • Im Standardmodus liest das Programm nur den eingebetteten Text einer PDF. Für gescannte Seiten, Text in Bildern, Tabellen, Formeln und Abbildungen nutze die strukturierte PDF-Aufbereitung.
  • Eine Web-Oberfläche und ein Container für Proxmox sind noch nicht vorhanden.

Der erste Durchlauf

In fünf Schritten zum ersten Deck

Dieses Beispiel nutzt Ollama auf deinem Computer. Deine Dokumente bleiben dabei lokal.

1

Python vorbereiten

Installiere Python 3.11 oder neuer. Öffne ein Terminal im Projektordner.

python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
2

Ollama vorbereiten

Installiere und starte Ollama. Lade ein Modell. Dieses Beispiel verwendet llama3.2.

ollama pull llama3.2
3

Dokument bereitstellen

Lege zum Beispiel die Datei skript.pdf im Projektordner ab. Die Datei muss lesbaren Text enthalten.

4

Karten erzeugen

Führe diesen Befehl aus. Das Programm erstellt höchstens 50 Karten.

anki-flashcards generate skript.pdf \
  --output output/biologie.apkg \
  --deck "Biologie::Grundlagen" \
  --model ollama/llama3.2 \
  --limit 50 \
  --json output/biologie.cards.json
5

Prüfen und importieren

  1. Öffne output/biologie.cards.json in einem Texteditor.
  2. Korrigiere falsche oder unklare Karten.
  3. Exportiere die geprüften Karten mit export erneut, falls nötig.
  4. Öffne Anki und importiere output/biologie.apkg.

Vor dem ersten Befehl

Vier Regeln, die du kennen musst

Neue Datei oder Erweiterung?

Ohne --extend: Die Zieldatei darf noch nicht existieren. Das Programm schützt sie vor dem Überschreiben.

Mit --extend: Die .apkg-Datei muss existieren. Das Programm ergänzt das angegebene Deck. Vorhandene Karten und Lernstände bleiben erhalten.

--no-extend verlangt ausdrücklich eine neue Datei. Das ist vor allem bei einer YAML-Konfiguration nützlich.

Welche Werte gewinnen?

Das Programm liest Werte in dieser Reihenfolge. Ein späterer Wert ersetzt den vorherigen Wert:

  1. Standardwert des Programms
  2. YAML-Konfiguration oder Modellprofil
  3. Ausdrücklich gesetzte Option in deinem Befehl

Eine Option im Befehl hat immer Vorrang. Die Datei .env liefert nur Zugangsdaten. Sie überschreibt keine Modelle oder Endpunkte.

Wo sucht das Programm Dateien?

Ein relativer Pfad in deinem Befehl gilt ab dem aktuellen Ordner. Beispiel: input/skript.pdf.

Ein reiner Dateiname kann auch aus input_dir in der YAML-Datei kommen. Beispiel: skript.pdf.

Relative Pfade innerhalb der YAML-Datei gelten ab dem Ordner dieser YAML-Datei.

Wie heißt das Ziel?

Ohne --output brauchst du output_dir in der YAML-Datei. Das Programm verwendet dann den Namen der Eingabedatei mit der Endung .apkg.

Ohne --deck verwendet generate den Dateinamen ohne Endung. Mit --deck "Biologie::Zellen" entsteht ein Unterdeck.

Fehlende Zielordner erstellt das Programm automatisch.

Sichere deine Daten.

Lege eine Sicherung deiner Anki-Sammlung an, bevor du ein erweitertes Paket importierst. Das Programm arbeitet nur an der angegebenen Paketdatei.

Die vollständige Referenz

Alle Befehle und Optionen

Die Schreibweise ist immer anki-flashcards, danach der Befehl und seine Optionen. Öffne die Bereiche für jede Einzelheit.

generate

Dokument → Karten → APKG

Erstellt Karten aus einem lokalen Dokument. Ein KI-Modell ist erforderlich. Der Befehl kann ein neues Paket erstellen oder ein Paket erweitern.

anki-flashcards generate EINGABE [OPTIONEN]
Argument: input_file
input_filePflicht · Datei

Gib den Pfad zur Quelldatei an. Erlaubt sind .pdf, .docx, .html, .htm, .md, .markdown und .txt.

Die Datei darf höchstens 100 MiB groß sein. Eine Textdatei muss UTF-8 verwenden. Ein reiner Dateiname kann durch input_dir aufgelöst werden.

Optionen für Ziel und Deck
--output, -oPfad · bedingt erforderlich

Gib die Zieldatei mit der Endung .apkg an. Diese Option ist erforderlich, wenn kein output_dir konfiguriert ist.

Ohne --extend muss die Datei neu sein. Mit --extend muss sie bereits existieren. Fehlende Ordner werden erstellt.

--deck, -dText · optional

Gib den Namen des Zieldecks an. Ohne diese Option gilt der Name aus generation.deck oder der Eingabedateiname ohne Endung.

Mit :: erstellst du ein Unterdeck, zum Beispiel Biologie::Genetik. Beim Erweitern muss dieser Name zum gewünschten Deck passen.

--extend / --no-extendSchalter · Standard: neue Datei

--extend ergänzt ein vorhandenes Paket. Doppelte Fragen werden übersprungen. Fehlt das Deck, wird es im Paket angelegt.

--no-extend verlangt eine neue Zieldatei. Beide Formen überschreiben den YAML-Wert extend.

--subdecks / --no-subdecksSchalter · Standard: aus

--subdecks lässt das KI-Modell jede Karte einem Unterdeck zuordnen. --deck ist dann das übergeordnete Deck, zum Beispiel der Name einer Vorlesung. Die Karten landen in Deck::Kapitel. Das Modell orientiert sich an den Kapitelüberschriften im Dokument.

Mit --extend liest das Programm die vorhandenen Unterdecks und bis zu fünf Beispielfragen je Unterdeck. Es sendet diese Angaben an das Modell. Das Modell verwendet passende Unterdecks wieder und legt nur bei Bedarf neue an. --no-subdecks schaltet einen YAML-Wert subdecks: true ab. Siehe Vorlesung mit Unterdecks.

--jsonPfad · optional

Speichert die Karten zusätzlich als UTF-8-JSON-Datei. Nutze diese Datei zur Prüfung und zum erneuten Export ohne KI.

Ein relativer Pfad gilt ab dem aktuellen Ordner. Fehlende Ordner werden erstellt. Eine vorhandene JSON-Datei wird ersetzt.

Optionen für Modell und Provider
--model, -mText · erforderlich ohne Profil

Gib das Modell als provider/modell an. Beispiele: ollama/llama3.2 oder openai/gpt-4o-mini.

Nutze normalerweise das Modell aus deinem YAML-Profil. Ein direkter Modellname hat Vorrang vor dem Profilmodell. Die alte Variable ANKI_MODEL wird nicht ausgewertet.

--profileText · optional

Wählt ein benanntes Profil aus der YAML-Datei. Das Profil kann Modell, Endpunkt, Timeout, PDF-Modus und den Namen der Schlüsselvariable enthalten.

--api-baseURL · optional

Ändert den Endpunkt des Providers. Nutze dies für einen kompatiblen eigenen Server oder eine abweichende Provider-Adresse.

Setze den Endpunkt normalerweise als api_base im YAML-Profil. Ohne Angabe verwendet das Programm den Standard des Providers. Die alte Variable LLM_API_BASE wird nicht ausgewertet.

--timeoutSekunden · 1 bis 3600 · Standard: 180

Begrenzt die Wartezeit für eine Provider-Anfrage. Nach Ablauf bricht das Programm die Anfrage mit einem Fehler ab.

Optionen für Inhalt und Umfang
--limit, -nGanzzahl ≥ 0 · Standard: 50

Begrenzt die Gesamtzahl der Karten über alle Textabschnitte. Mit --limit 25 entstehen höchstens 25 Karten.

--limit 0 entfernt die zahlenmäßige Grenze. Jeder Textabschnitt wird einmal verarbeitet. Nutze diesen Modus mit Bedacht. Kosten und unbrauchbare Karten können steigen.

--language, -lText · Standard: Deutsch

Bestimmt die Sprache der Fragen und Antworten. Beispiel: --language Englisch. Das Quelldokument darf eine andere Sprache enthalten.

--instructionsText · optional

Gibt zusätzliche Anweisungen an das Modell. Setze den Text in Anführungszeichen.

Beispiel: --instructions "Stelle kurze Verständnisfragen.". Eine leere Angabe überschreibt eine YAML-Anweisung.

--chunk-sizeZeichen · 1000 bis 100000 · Standard: 24000

Begrenzt die Menge des lokal extrahierten Textes pro KI-Anfrage. Große Dokumente werden auf mehrere Anfragen verteilt.

Benachbarte Abschnitte teilen 500 Zeichen, höchstens aber ein Viertel der Abschnittsgröße. Bei --chunk-size 1000 sind es also 250 Zeichen, ab 2000 immer 500. Dadurch geht weniger Zusammenhang an den Grenzen verloren. Der Wert beeinflusst nicht die native PDF-Verarbeitung.

Optionen für Konfiguration und PDF
--configPfad · optional

Wählt eine YAML-Konfigurationsdatei. Alternativ gilt ANKI_CONFIG. Ohne Angabe sucht das Programm nach config.yaml im aktuellen Ordner.

Eine fehlende Standarddatei ist kein Fehler. Eine ausdrücklich angegebene fehlende Datei ist ein Fehler.

--pdf-mode localStandard

Liest den Text der PDF auf deinem Computer. Nur dieser Text wird an das Modell gesendet. Diese Option ist die sichere Standardwahl für lokale Modelle.

--pdf-mode structuredAusdrückliche Aktivierung · Extra pdf

Bereitet die PDF lokal mit Docling auf: Texterkennung für Bilder und Scans, Tabellen als Markdown-Tabellen, Formeln als LaTeX und Abbildungen als markierte Beschreibungen. An das Kartenmodell geht danach nur Text.

Nur .pdf-Dateien sind erlaubt. Der Modus braucht eine GPU; ohne GPU bricht er ab und empfiehlt native oder local. Ohne das installierte Extra pdf nennt das Programm den Installationsbefehl. Einzelheiten stehen im Abschnitt PDF lokal vollständig aufbereiten.

--pdf-mode nativeAusdrückliche Aktivierung

Lädt die vollständige Original-PDF zu einem freigegebenen OpenAI-Modell hoch. Die lokale PDF-Textextraktion wird übersprungen.

Andere Dateiformate und nicht freigegebene Modelle werden abgelehnt. Es gibt keinen automatischen Wechsel zurück zur lokalen Verarbeitung.

--help, -hSchalter

Zeigt die Hilfe für generate an. Das Programm erzeugt keine Karten.

Optionen für die strukturierte PDF-Aufbereitung

Diese Optionen wirken nur mit --pdf-mode structured. Jede überschreibt den gleichnamigen Wert in pdf_conversion der YAML-Datei.

--formulas / --no-formulasSchalter · Standard: an

Erkennt Formeln als LaTeX, zum Beispiel \varphi(\omega) = \varphi_{out} - \varphi_{in}. Auf einer CPU dauert das auf formelreichen Seiten bis etwa zwei Minuten pro Seite.

--no-formulas spart diese Zeit. Formeln erscheinen dann als [Formel S. N – nicht ausgewertet].

--force-ocr / --no-force-ocrSchalter · Standard: aus

Liest jede Seite per Texterkennung statt über die eingebettete Textebene. Nutze das bei fehlerhafter oder unlesbarer Textebene. Bildbereiche und Scans werden auch ohne diese Option erkannt.

--allow-unreadable / --no-allow-unreadableSchalter · Standard: Abbruch

Ohne diese Option bricht der Lauf ab, wenn eine Formel, eine Abbildung oder eine Seite nicht gelesen werden kann. Das passiert vor jeder KI-Anfrage. Die Meldung nennt die Stellen.

--allow-unreadable setzt stattdessen gemeldete Platzhalter wie [nicht lesbar: Formel S. 3].

--allow-cpu / --no-allow-cpuSchalter · Standard: aus

Ohne GPU bricht der strukturierte Modus vor jeder Arbeit ab. --allow-cpu erlaubt den Betrieb auf dem Prozessor trotzdem. Rechne dann mit sehr langen Laufzeiten; nutze das nur für kurze Dokumente oder zusammen mit --no-formulas.

--picture-backendlocal | profile | none · Standard: local

Wählt, welches Modell Abbildungen beschreibt. local nutzt ein Bildmodell auf deinem Computer. profile nutzt ein Modellprofil und sendet dafür Bildausschnitte an dessen Provider. none beschreibt nichts und behält Abbildungen als Platzhalter mit dem darin erkannten Text.

--picture-profileProfilname · optional

Profil für --picture-backend profile. Ohne Angabe gilt pdf_conversion.pictures.profile, sonst das Profil der Kartenerzeugung. Das Profil muss image_input: true setzen.

--source-textPfad · optional · neue Datei

Speichert den aufbereiteten Text als Markdown. Prüfe damit die Vollständigkeit. Eine vorhandene Datei wird nie überschrieben; der Lauf bricht dann vor der Aufbereitung ab.

Die gespeicherte Datei kannst du mit --pdf-mode local erneut verarbeiten. Die langsame Aufbereitung entfällt dann.

anki-flashcards generate skript.pdf \
  --output output/deck.apkg \
  --deck "Biologie" \
  --model ollama/llama3.2 \
  --limit 50

export

Geprüftes JSON → APKG

Wandelt eine vorhandene Karten-JSON-Datei in ein Anki-Paket um. Das Programm ruft dabei kein KI-Modell auf. Es entstehen keine neuen KI-Kosten.

anki-flashcards export KARTEN.json [OPTIONEN]
Argument und alle Optionen
cards_filePflicht · JSON-Datei

Gib eine Karten-JSON-Datei mit schema_version: 1 an. Diese Datei stammt normalerweise aus generate --json. Ein reiner Dateiname kann durch input_dir aufgelöst werden. Tags aus mehreren Wörtern werden beim Einlesen zu einem Tag mit Unterstrichen zusammengezogen (Ohmsches Gesetz → Ohmsches_Gesetz), weil Anki keine Leerzeichen in Tags kennt; dasselbe gilt für Tags in KI-Antworten.

Hat eine Karte das Feld subdeck, legt das Programm sie in --deck::subdeck ab. Du kannst die Zuordnung also vor dem Export in der JSON-Datei ändern.

--output, -oPfad · bedingt erforderlich

Gib die Zieldatei mit der Endung .apkg an. Erforderlich, wenn output_dir fehlt. Die Regeln für neue und erweiterte Dateien entsprechen generate.

--deck, -dText · bedingt erforderlich

Gib das Zieldeck an. Diese Option ist erforderlich, wenn generation.deck in der YAML-Datei fehlt. Der gespeicherte Deckname in der JSON-Datei ersetzt diese Angabe nicht.

--extend / --no-extendSchalter · Standard: neue Datei

Erweitert ein vorhandenes Paket oder verlangt eine neue Datei. Die Option überschreibt den YAML-Wert extend.

--configPfad · optional

Wählt die YAML-Konfiguration für Ausgabeordner, Deck und Extend-Standard. Alternativ gilt ANKI_CONFIG.

--help, -hSchalter

Zeigt die Hilfe für export an. Es wird keine Datei erzeugt.

anki-flashcards export output/biologie.cards.json \
  --output output/biologie.apkg \
  --deck "Biologie"

config show

Einstellungen prüfen

Zeigt die tatsächlich verwendeten Einstellungen als JSON. Du siehst auch, ob ein Wert aus dem Programm, der YAML-Datei, der Umgebung oder deinem Befehl stammt.

API-Schlüssel werden nicht angezeigt. Die Ausgabe enthält nur set (hidden) oder not set. Das Programm erstellt keine Karten und ruft kein Modell auf.

anki-flashcards config show EINGABE [OPTIONEN]
Argument und Ausgabe
input_filePflicht · Pfad oder Dateiname

Gib die geplante Eingabedatei an. Das Programm benötigt diesen Namen, um Eingabeordner, Ausgabedatei und Standarddeck zu berechnen. Die Datei muss für diese Vorschau nicht verarbeitet werden.

Herkunft sourcesJSON-Feld

built-in bedeutet Programmstandard. config bedeutet YAML oder Profil. cli bedeutet dein Befehl. Zugangsdaten haben keine eigene Herkunftsschicht in dieser Anzeige.

models download

Modelle vorab laden

Lädt alle Modelle, die die strukturierte PDF-Aufbereitung braucht, in den Modellordner des Projekts. Danach arbeitet der Modus ohne Internet. Ohne diesen Befehl lädt der erste strukturierte Lauf die Modelle selbst und kündigt das an.

Geladen werden die Docling-Modelle für Layout, Tabellen, Texterkennung und Bildklassen, das Formelmodell und bei local das Bildmodell. Alles landet in pdf_conversion.models_dir, standardmäßig models/ neben der YAML-Datei. Nichts wird in ~/.cache geschrieben.

anki-flashcards models download [OPTIONEN]
Alle Optionen
--configPfad · optional

Wählt die YAML-Datei. Ihr Ordner bestimmt den relativen Modellordner. Alternativ gilt ANKI_CONFIG.

--formulas / --no-formulasSchalter · Standard: YAML, sonst an

Lädt das Formelmodell mit oder ohne. Ohne Angabe gilt pdf_conversion.formulas.

--picture-backendlocal | profile | none

Nur bei local wird das Bildmodell geladen. Ohne Angabe gilt der YAML-Wert.

--help, -hSchalter

Zeigt die Hilfe für models download.

anki-flashcards models download --config config.yaml

Weniger tippen

YAML-Konfiguration verwenden

Die YAML-Datei ist die Hauptkonfiguration. Speichere dort Modelle, Endpunkte, Ordner und Optionen. Die Datei .env enthält nur Zugangsdaten.

cp config.example.yaml config.yaml
cp .env.example .env
Vor dem ersten Lauf vorbereiten
  1. Wähle in config.yaml ein Profil mit default_profile.
  2. Prüfe Modellname und api_base in diesem Profil.
  3. Installiere ein Ollama-Modell vorher auf deinem Server oder erstelle einen API-Token beim Cloud-Anbieter.
  4. Trage den benötigten Token in .env ein. Lösche oder ersetze dafür den Platzhalter.
  5. Prüfe alles mit anki-flashcards config show dokument.pdf --config config.yaml.

Die alten Variablen ANKI_MODEL und LLM_API_BASE gehören nicht in .env. Sie werden nicht ausgewertet. ANKI_CONFIG wählt nur den Pfad der YAML-Datei.

Wichtig für deine Daten

Drei Wege, eine PDF zu lesen

local – Standard

Das Programm liest den eingebetteten PDF-Text auf deinem Computer. Es sendet Textabschnitte an das gewählte Modell.

Bei Ollama bleibt die Verarbeitung auf deinem Computer. Bei einem Cloud-Provider verlassen die Textabschnitte deinen Computer.

Text in Bildern, Scans, Tabellenstrukturen und Formeln gehen dabei verloren oder kommen verstümmelt an.

structured – lokal und vollständig

Docling bereitet die PDF auf deinem Computer auf: Texterkennung, Tabellen, Formeln und Abbildungsbeschreibungen. Danach geht nur Text an das Kartenmodell.

Das funktioniert mit jedem Kartenmodell. Es braucht das Extra pdf und eine GPU. → Anleitung

native – ausdrücklich wählen

Das Programm lädt die vollständige Original-PDF zu OpenAI hoch. Es findet keine lokale Textextraktion statt.

Freigegeben sind derzeit gpt-4o-mini, gpt-4o, gpt-4.1 und datierte Snapshots dieser Modelle.

Die Datei muss kleiner als 50 MiB sein. Andere Provider und Dateiformate werden abgelehnt.

Native Verarbeitung überträgt deine Originaldatei.

Nutze sie nur, wenn du diesen Upload ausdrücklich möchtest. Text und Seitenbilder können Token- und Uploadkosten verursachen. Die Modelle können zusätzliche Kontextgrenzen haben.

Das Programm setzt store=false und löscht die hochgeladene Datei anschließend. Bei einem Löschfehler erhältst du eine Warnung mit der Datei-ID. Eine separate Aufbewahrung durch den Provider kann trotzdem gelten.

anki-flashcards generate dokument.pdf \
  --config config.yaml \
  --profile openai-native-pdf

Bilder, Tabellen und Formeln nicht verlieren

PDF lokal vollständig aufbereiten

Vorlesungsfolien enthalten oft Diagramme, Schaltbilder, Tabellen und Formeln. Der Standardmodus liest davon nur den eingebetteten Text. Der Modus structured wandelt die PDF auf deinem Computer mit Docling in Text um. Dabei arbeiten mehrere lokale KI-Modelle zusammen.

Dieser Modus braucht eine GPU.

Geeignet sind NVIDIA (CUDA), AMD mit ROCm-Unterstützung, Apple Silicon (MPS) und Intel (XPU). Auf dem Prozessor allein ist die Aufbereitung sehr langsam: Eine 15-seitige Vorlesung mit Formeln war nach über 50 Minuten noch nicht fertig. Das Programm prüft die GPU vor jeder Arbeit und bricht ohne GPU ab.

Ohne GPU hast du zwei Wege: --pdf-mode native lässt das KI-Modell des Providers die PDF lesen (Upload). --pdf-mode local nutzt nur den eingebetteten Text. Mit --allow-cpu erzwingst du den langsamen Betrieb trotzdem.

1

Einmal installieren

Installiere PyTorch passend zu deiner GPU. Den genauen Befehl zeigt die Auswahl auf pytorch.org. Installiere danach das Extra pdf in die Projektumgebung.

.venv/bin/python -m pip install --no-cache-dir torch torchvision
.venv/bin/python -m pip install --no-cache-dir -e '.[pdf]'
2

Modelle laden

Lade die Modelle vorab in den Ordner models/ des Projekts. Danach geht es ohne Internet. Ohne diesen Schritt lädt der erste Lauf die Modelle.

anki-flashcards models download
3

Vorlesung aufbereiten

Wähle --pdf-mode structured. Speichere den aufbereiteten Text mit --source-text, um ihn zu prüfen.

anki-flashcards generate input/EL1_WS26_V03.pdf \
  --output output/el1.apkg --deck EL1 --subdecks \
  --pdf-mode structured \
  --source-text output/texte/EL1_WS26_V03.md

Das Kartenmodell erfährt, dass Abbildungsbeschreibungen maschinell erstellt sind. Es darf daraus keine weiteren Fakten erfinden.

Im Test mit Vorlesungsfolien hat SmolVLM-256M Schaltbilder und Diagramme oft falsch beschrieben und Inhalte erfunden. Der Text in Abbildungen wird trotzdem per OCR übernommen. Für gute Beschreibungen nutze --picture-backend profile mit einem größeren Vision-Modell auf einem eigenen Server. Ohne ein solches Modell ist --picture-backend none die vorsichtigere Wahl.

anki-flashcards generate input/ET2_04_FH_WS26_leer.pdf \
  --output output/et2.apkg --pdf-mode structured \
  --picture-backend profile --picture-profile ollama-vision
Speicherort, Laufzeit und Arbeitsspeicher

Alles, was der Modus herunterlädt oder zwischenspeichert, liegt in einem Ordner: pdf_conversion.models_dir, standardmäßig models/ neben der YAML-Datei. Das Programm schreibt nichts in ~/.cache. Der Ordner ist von Git ausgeschlossen. Modelle, die Ollama verwaltet, bleiben in der Ablage von Ollama.

Die folgenden Werte zeigen, warum eine GPU nötig ist. Gemessen wurde auf einem Laptop ohne nutzbare GPU (12 CPU-Threads, 14 GB Arbeitsspeicher):

  • Installation: etwa 2,2 GB in .venv; Modelle etwa 1,9 GB in models/.
  • Text, Layout, Tabellen und OCR ohne Formeln: etwa 8 bis 12 Sekunden pro Seite.
  • Formeln: auf formelreichen Seiten etwa zwei Minuten pro Seite.
  • Lokale Bildbeschreibung: etwa 15 bis 25 Sekunden pro Abbildung.
  • Arbeitsspeicher: etwa 2,5 bis 3 GB.

Eine integrierte AMD-Radeon-Vega-GPU hilft dabei nicht: ROCm unterstützt sie nicht offiziell, und sie hat sehr wenig eigenen Speicher.

Nichts geht stillschweigend verloren.

Kann eine Formel, eine Abbildung oder eine Seite nicht gelesen werden, bricht der Lauf vor jeder KI-Anfrage ab und nennt die Stellen. Mit --allow-unreadable erscheinen stattdessen gemeldete Platzhalter. Fehlen Docling oder eine GPU, nennt das Programm, was zu tun ist. Es wechselt nie selbst zu local oder native.

Ordnung nach Kapiteln

Eine Vorlesung mit KI-Unterdecks aufbauen

Ein Deck steht für eine Vorlesung. Die Unterdecks stehen für die Kapitel. Mit --subdecks ordnet das KI-Modell jede neue Karte einem passenden Kapitel zu.

1

Erstes Skript

Erstelle ein neues Paket. Das Modell bildet die Unterdecks aus den Kapitelüberschriften des Dokuments.

anki-flashcards generate vl-01.pdf \
  -o output/el1.apkg \
  -d "Elektrotechnik 1" \
  --subdecks
2

Weitere Skripte

Erweitere dasselbe Paket mit --extend. Das Modell kennt jetzt die vorhandenen Kapitel und verwendet passende wieder.

anki-flashcards generate vl-02.pdf \
  -o output/el1.apkg \
  -d "Elektrotechnik 1" \
  --subdecks --extend
3

Ergebnis prüfen

Die Ausgabe nennt die neuen Karten je Unterdeck. Prüfe alle Decks mit decks.

anki-flashcards decks output/el1.apkg
So arbeitet der Unterdeck-Modus
  • Jede Karte kommt in genau ein Unterdeck Deck::Kapitel. Ein Unterdeckname hat eine Ebene ohne :: und höchstens 100 Zeichen.
  • Beim Erweitern liest das Programm die direkten Unterdecks des Decks und bis zu fünf Beispielfragen je Unterdeck. Das Paket bleibt dabei unverändert.
  • Namen, die sich nur in Groß- und Kleinschreibung oder Leerzeichen unterscheiden, werden zu einem Namen zusammengeführt.
  • Doppelte Fragen erkennt das Programm im ganzen Deck mit allen Unterdecks. Vorhandene Karten und Lernstände bleiben erhalten.
  • Mit --json enthält jede Karte das Feld subdeck. Ändere das Feld bei Bedarf und exportiere mit export erneut.
  • Der Modus funktioniert lokal und mit --pdf-mode native.
Zusätzliche Daten gehen an den Provider.

Mit --subdecks --extend sendet das Programm die Namen der vorhandenen Unterdecks und einige Beispielfragen an das Modell. Nutze für vertrauliche Inhalte ein lokales Modell.

Prüfe die Zuordnung.

Das Modell kann Karten falsch einordnen oder ein Kapitel doppelt benennen. Prüfe die Unterdecks mit --json oder in Anki. Verschiebe Karten in Anki bei Bedarf.

Feste Begriffe

Kurzes Glossar

APKG

Eine Paketdatei für Anki. Sie enthält Decks, Karten und zugehörige Daten. Du importierst sie in Anki.

Deck

Eine Sammlung von Karteikarten in Anki. Ein Unterdeck wird mit :: benannt.

Unterdeck

Ein Deck innerhalb eines anderen Decks, zum Beispiel Elektrotechnik 1::Netzwerke. Mit --subdecks bildet das KI-Modell die Unterdecks.

JSON

Eine Textdatei mit strukturierten Daten. Hier enthält sie die Karten zur Prüfung und zum erneuten Export.

YAML

Eine lesbare Konfigurationsdatei. Sie speichert Standardwerte und Modellprofile, aber keine API-Schlüssel.

Profil

Ein benannter Satz von Modelleinstellungen in der YAML-Datei. Du wählst ihn mit --profile.

Provider

Der Dienst, der das KI-Modell bereitstellt. Beispiele sind Ollama, OpenAI, Anthropic, Gemini und Moonshot.

Chunk

Ein Abschnitt des extrahierten Textes. Große Dokumente werden in mehrere solcher Abschnitte aufgeteilt.

Native PDF-Verarbeitung

Der Upload der Original-PDF an ein geeignetes OpenAI-Modell. Die lokale Textextraktion entfällt.

Docling

Ein Open-Source-Werkzeug, das PDFs mit lokalen KI-Modellen in strukturierten Text umwandelt. Es läuft im Modus structured.

OCR

Texterkennung. Sie liest Text aus Bildern und gescannten Seiten.

Bildmodell

Ein KI-Modell, das Bilder versteht. Es beschreibt Abbildungen in Worten, damit ein reines Textmodell sie nutzen kann.
